# Requirements Analysis 질문

요청: "메인 화면의 각 item의 넓이를 키우고, 클릭시 detail 화면에 notion의 내용이 포함되는 기능을 추가하려 함."

## Q1. 메인 화면 아이템 넓이를 어떻게 키울까요?

맥락: 현재 커버 이미지가 없는 글도 카드가 `180px | 본문` 2열로 고정돼 제목·설명이 180px 첫 열에 갇혀 있습니다(지금 글은 모두 커버 이미지 없음). 그 밖에 컨테이너 `max-w-6xl`, 왼쪽 220px Index 사이드바, 설명 `max-w-2xl`도 폭을 제한합니다.

A. 카드 레이아웃만 고침 — 커버 이미지가 없으면 1열로 전체 폭 사용, 설명 폭 제한(`max-w-2xl`) 제거
B. A + 페이지 컨테이너를 넓힘(`max-w-6xl` → `max-w-7xl`)
C. A + 왼쪽 Index 사이드바를 없애 목록이 페이지 폭을 모두 사용
X. Other (please specify)

[Answer]: A

## Q2. 아이템의 어느 부분을 클릭하면 상세 화면으로 이동할까요?

맥락: 지금은 제목 글자만 링크입니다. 카드 안에 태그 링크가 있어 카드 전체를 링크로 만들 때는 태그 클릭과 겹치지 않게 처리해야 합니다.

A. 카드 전체 클릭 시 상세로 이동(태그는 계속 태그 링크로 동작)
B. 지금처럼 제목만 클릭
X. Other (please specify)

[Answer]: A

## Q3. 상세 화면에서 Notion 본문을 어느 수준까지 보여줄까요?

맥락: 본문은 이미 Notion → Markdown으로 변환돼 있습니다. Notion에 직접 업로드한 이미지는 서명 URL이라 약 1시간 뒤 만료되므로, 정적 빌드 후에는 이미지가 깨질 수 있습니다.

A. 제목·메타정보 + 본문(문단, 제목, 목록, 표, 체크리스트, 인용, 코드 하이라이트). 이미지는 Notion URL을 그대로 사용(만료 문제는 다음 작업으로 미룸)
B. A + 빌드할 때 Notion 이미지를 내려받아 사이트에 함께 배포(만료 방지)
C. 본문 텍스트만 기본 Markdown으로 표시(코드 하이라이트·표 등 없이)
X. Other (please specify)

[Answer]: A

## Q4. 이번 작업을 어떻게 검증할까요?

맥락: 현재 저장소에는 테스트 프레임워크와 CI가 없습니다. 검증은 `yarn type-check`, `yarn lint`, `yarn build`(정적 export 시 상세 페이지 HTML 생성 확인)로 할 수 있습니다.

A. 테스트 도구 추가 없이 type-check / lint / build와 상세 페이지 생성 결과 확인으로 검증
B. 테스트 도구(Vitest)를 도입하고 핵심 로직(예: 카드 레이아웃 분기, Markdown 렌더링)에 단위 테스트 추가
X. Other (please specify)

[Answer]: B
